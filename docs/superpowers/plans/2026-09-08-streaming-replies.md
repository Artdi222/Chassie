# Streaming Hermes replies into speech

Approved in discussion after the user accepted reducing the wait for Hermes's complete reply. Preserve the English voice, bounded device playback, manual Stop and personal/guest cancellation.

1. Add an authenticated SSE text iterator matching the installed Hermes chat-completions contract. Handle network fragmentation, errors, explicit completion, revision invalidation and provisional interrupted history. Retain the nonstreaming method for compatibility.
2. Add a pure incremental sentence/emotion parser with tests for arbitrary fragment boundaries, decimals, abbreviations, emotion changes and bounded unpunctuated text.
3. Receive text in one task into a bounded sentence queue; synthesize/play in another with one next-sentence prefetch. A failure in either task cancels and joins the other. Start speech before the network stream completes; only physically drained sentences enter interrupted spoken history.
4. Update one browser bubble as text arrives, mark interruption, and hydrate reconnects without duplicate partial messages. Preserve origin checks and guest clearing.
5. Test controlled delayed SSE delivery proving first playback precedes stream completion, cancellation during stream/prefetch/playback, provider errors, queue bounds and browser updates. Run full suite and one bounded synthetic live attempt; separate local protocol proof from upstream provider availability and actual acoustic latency.

Baseline TTS-only measurement on this machine: three short English sentences produced first PCM after 1.030 / 1.500 / 1.087 seconds. This is not an end-to-end or before/after benchmark. Streaming the text does not change Edge's per-sentence in-memory decode into incremental PCM decoding.

## Implemented and verified

- Hermes chat SSE handles fragmented UTF-8/events, keepalives, role-only chunks, reasoning/tool metadata exclusion, clean `stop` + `[DONE]`, error/truncation/disconnect and bounded input. Known provider-error prefixes split across deltas are withheld before speech/history. No automatic second request or batch fallback is made after streaming starts.
- `SpeechChunker` preserves emotion ownership across arbitrary fragment boundaries, protects decimals/common abbreviations and caps unpunctuated segments at 350 characters. Conservative abbreviation boundaries may wait for more text; the final fragment flushes only after valid stream completion.
- Orchestrator receives and plays concurrently through eight queued text segments plus one prefetched sentence. A real local HTTP/SSE test holds the server stream open until the fake output device begins its first drain, proving the first playback does not depend on full reply completion. Slow playback applies backpressure rather than collecting unbounded text/PCM.
- Browser text updates one bubble, preserves unknown bracket text, hydrates active stream IDs on reconnect, and marks interrupted answers. History hydration is serialized with participant/clear controls and has a bounded send timeout. Privacy cancellation does not rebroadcast the old response during teardown.
- Review found a delayed native microphone mutation race; capture changes are now serialized and shielded/joined on cancellation. Tests reproduce delayed mute followed by Stop and repeated cancellation. Device PCM cancellation still rejects stale generations.
- Full final suite: **138 passed in 5.46 s**. Python compilation and JavaScript syntax checks passed. Initial red evidence included use of the old full-response method and old personal stream rebroadcast after guest cancellation; both regressions now pass.
- One bounded live streaming attempt: authenticated health passed, but Hermes returned a sanitized model-provider failure before any valid response. `.test-artifacts/hermes-stream-live-check.json` records the result without prompt content or credentials. No microphone/camera recording or audible playback was performed. Real provider latency improvement and acoustic first-sound timing remain unmeasured.

Restart the Chassie backend and reload the browser to use the new WebSocket protocol. Overlay startup is unchanged. `hermes.stream_timeout` defaults to 180 seconds total; `stream_read_timeout` is now 75 seconds between network data (initially 30, corrected below). Logged timing fields distinguish first text, sentence, PCM, queued audio, network completion and playback completion; queued audio is not a measurement of sound reaching the listener.

## Subsequent live latency diagnosis

On 8 September at approximately 13:56 WIB, a synthetic direct SSE request succeeded: HTTP headers 0.007 s, role-only chunk 0.008 s, first text 22.839 s, clean stop/DONE 22.854 s. Hermes logged a 7.0 s model call with 15,795 input tokens and no tool turns. Approximately 15.8 s preceded inference, including repeated unsuccessful context-length discovery during agent initialization. This is a gateway baseline without STT/TTS/audio, not evidence of an end-to-end speedup. The user confirmed round-robin routing, so underlying model latency is not controlled. See [diagnosis and follow-up](../../hermes-setup.md) before choosing a context-length override; no Hermes configuration was changed by this investigation.

## Web reply timing out before any text

The user confirmed the web notice `Hermes streaming request timed out. Please retry.` Installed Hermes uses a 30-second keepalive interval, emitted by an idle queue poll. Chassie's previous 30-second socket-read timeout raced that heartbeat. Defaults and project config now allow 75 seconds without data, retaining the 180-second total deadline and explicit cancellation. Timeout notices distinguish missing network data from the total deadline; logs record failure type and elapsed timing without prompt/provider payloads.

Turn failures now emit a chat-scoped notice rendered as an accessible alert in the conversation as well as the sidebar. The frontend asset version was incremented. Three regression cases failed before the fix (delayed heartbeat under default and project config, chat-scoped failure delivery); all pass afterward. Tests scale production deadlines and use actual loopback SSE delivery. Total/read timeout bounds and cancellation remain covered. Full suite: **142 passed in 7.42 s**; JavaScript syntax and Python compilation passed. Browser verification includes the timeout alert with the mobile sidebar hidden (`.test-artifacts/chat-timeout-mobile.png`). Restart the existing Chassie backend and reload the page to load the fix; no Hermes config/restart is needed for this change.

Live verification used an isolated Chassie WebSocket server, temporary empty memory, real Hermes and English Edge TTS, and fake microphone/camera/output devices. The first attempt delivered text after 83.708 s, proving the stream survived the former deadline, but the harness omitted TTS initialization. After correcting the harness, the next synthetic turn completed successfully: first text 14.185 s, first PCM 15.100 s, audio queued 15.102 s. `.test-artifacts/web-turn-live-check.json` records that successful run without response text or credentials. The timing variation is not proof that changing the timeout speeds up the model. No physical audio playback or modification/restart of the user's running backend was performed.
